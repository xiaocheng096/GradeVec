# 阅维 GradeVec

**基于余弦相似度的作业两两查重与智能批改工具。**

单文件网页，双击即用。分词、TF-IDF 向量化、余弦相似度全部在浏览器本地完成，作业文本不上传任何服务器；只有当你主动填写自己的模型 Key 并开启「AI 评语」时，才会调用你指定的模型服务。

## 快速开始

```bash
# 方式一：直接双击
# 下载 index.html，双击用浏览器打开即可，无需安装任何东西

# 方式二：本地起一个静态服务（推荐，避免个别浏览器的本地文件限制）
python -m http.server 8000
# 然后访问 http://127.0.0.1:8000/index.html
```

也可以把 `index.html` 丢到任意静态托管（GitHub Pages、对象存储、内网服务器）上，它没有任何后端依赖。

> 仓库根目录只放这份免安装的单文件版。带多格式解析、AI 试用的完整版在 `cloud/`（`index.html` + `main.py`），入口见上方「完整版演示」。

## 功能特性

### 一、作业两两查重

| 能力 | 说明 |
|---|---|
| 批量导入 | 拖拽 `.txt` / `.md`（可多选），或直接粘贴文本 |
| 多份分隔 | 粘贴时用 `===` 或**连续两个空行**分隔；拖拽时文件名即作业标识 |
| 相似度矩阵 | N×N 热力矩阵，超过阈值（默认 70%，可调 30%–95%）的格子标红预警；矩阵下方是仿 Apple 的色阶胶囊（无描边、无滑块），当前值以大字号悬在正上方，悬浮色块时读数与白色游标同步 |
| 拖动定位 | 色阶条可直接拖动，拖到哪个分值就把矩阵里落在该分值 ±5% 的格子挑出来加框提亮、其余压暗；Esc 或点击色块退出 |
| 悬浮速览 | 鼠标移到色块或排行行，浮出小卡：两份作业名、相似度、判定标签、阈值刻度线；移开自动收起 |
| 两两对照 | **点任意色块**（或排行表任意一行）弹出对照面板：相似度、字面重合率、共用词、左右并排原文，连续 6 字以上完全相同的片段自动高亮 |
| 重复度排行 | Chart.js 柱状图 + 排行表，按相似度从高到低排序 |
| 导出 | 一键导出 `查重结果_<时间戳>.csv` |

### 二、比对批改

| 能力 | 说明 |
|---|---|
| 参考答案比对 | 以参考答案为基准，算出每份作业的余弦相似度并换算成百分制基础分 |
| 差异高亮 | 每张成绩卡上的**「对照高亮」**：与参考答案并排展示，**红色标出不同的地方，一致的地方不标**；纯本地字面比对，不调用 AI |
| 得分构成 | 基础分来自算法；开启 AI 评语后，模型在基础分锚点附近做小幅修正（±15 分内） |
| 个性化评语 | 逐份生成「得分点命中 / 失分原因 / 改进建议」；未配置 Key 时自动回落为算法说明 |
| 失败不空转 | 模型超时、返回不是合法 JSON、Key 失效，都会退回算法分并说明原因，不中断整批 |
| 成绩单导出 | 导出 `批改成绩单_<时间戳>.csv`，含相似度、基础分、最终分与评语 |

### 三、其它

| 能力 | 说明 |
|---|---|
| 纯本地计算 | 查重与算法打分不发任何网络请求，断网也能跑 |
| 配置本机保存 | Key、接口地址、模型名存在当前浏览器（`localStorage`），刷新后仍在 |
| 算法自检 | 内置断言用例（相似文本 > 80%、无关文本 < 20%），点一下验证引擎是否正常 |
| 参数可调 | 重复判定阈值、同义词归一、停用词过滤、AI 评语开关 |
| 移动端适配 | 窄屏自动切换单列布局 |

### 四、在线版（完整版）额外能力

在线版由 `cloud/index.html` + `cloud/main.py` 组成，前端保持单文件，解析与算力放在后端：

| 能力 | 说明 |
|---|---|
| 多格式导入 | `.docx` / `.pdf` / `.csv` / `.json` / `.txt` / `.md`，以及 `.java`、`.py`、`.js`、`.c`、`.go` 等 40 余种代码文件 |
| 文档解析 | `.docx` 用 python-docx 按正文顺序读段落与表格；`.pdf` 用 pdfplumber 逐页抽文字层；`.csv` 用 `csv.Sniffer` 猜分隔符；`.json` 递归取字符串叶子节点 |
| 前端零依赖 | 文件原样 POST 到 `/api/extract_text`，拿回纯文本后再进输入框——可以预览、二次编辑，也可以直接改完再算 |
| 失败有话说 | 格式不支持（415）、超体积（413）、解析失败（422：加密 PDF、扫描件没有文字层、损坏的 docx、JSON 语法错误）都会指出具体原因，而不是笼统的「导入失败」 |
| 口径一致 | 解析结果与粘贴文本走同一条 `同义词归一 → 分词 → TF-IDF → 余弦` 链路；`/api/check` 与 `/api/grade` 也直接接受这些格式 |
| 体积上限 | 纯文本/代码 ≤ 200KB，`.docx`/`.pdf`/`.csv`/`.json` ≤ 8MB；PDF 最多读 80 页，单次提取上限 12 万字（超出截断并提示） |

## 算法说明

```
同义词归一 → 中文分词 → 停用词过滤 → TF-IDF 向量化 → 余弦相似度 → 同义句加成 → 基础分（+ 可选 AI 评语）
```

**1. 分词**：优先用浏览器原生 `Intl.Segmenter` 做中文分词，缺失时自动降级为二元组切分；剔除纯标点、纯数字与停用词，英文按小写整词保留。

**2. 归一化**：分词前先做同义词替换（如「计算机」→「电脑」、「阀值」→「阈值」、「构成」→「组成」），避免同一概念因写法不同被判成两个无关词。词表覆盖 80 余组、约 270 个词条，包含计算机术语与「提高/提升」「负责/承担」「涵盖/涉及」这类通用表达——后者是同义句改写的主要来源。纯 ASCII 变体（`AI`、`PC`）带词边界，不会误伤 `main`、`email`、`training`。

**3. TF-IDF**：

```python
idf(t) = ln((N + 1) / (df(t) + 1)) + 1     # smooth_idf
tf(t,d) = 1 + ln(计数)                      # sublinear_tf，抑制长文本刷分
w(t,d) = tf(t,d) × idf(t)，再做 L2 归一化
```

批量查重时 **N 篇文档共用一套 IDF**，矩阵才有可比性。

**4. 余弦相似度**：`cos(A,B) = A·B / (‖A‖·‖B‖)`，取值 0–1。

**5. 同义句加成**：余弦按 TF-IDF 加权，措辞一换、词频一变分数就掉；而同义句改写的实质是「概念集合几乎相同，只是用词和语序不同」。因此再算一次同义归一后的词项集合重合度（Dice）：

```
dice = 2|A∩B| / (|A|+|B|)
ramp = clamp((cos - 0.40) / 0.20, 0, 1)      # 余弦不到 40% 视为话题不同，不加成
sim  = cos + 0.5 × max(0, dice - cos) × ramp
```

只在 `dice > cos` 时补差值，且最多补一半——**相似度只会上调、不会下调**，近重复仍是 100%，无关文本仍是 0%。

效果（同一组样例）：同义改写 0.56 → 0.81（71 → 88 分），同义句改写 0.48 → 0.60（64 → 74 分）；而「同一套实验模板、内容不同」的两段文字保持 0.29 不变，不会被套话抬分。

**6. 基础分换算**：`round(100 × sim^0.6)`，重合度低于 9% 时再乘一段软膝（`0.2 + sim/0.09 × 0.8`），避免零星词命中被抬到十几分。

0.6 次幂比早期的 0.75 次幂整体高 6–9 分，贴合「写了要点就该在及格线上下」的直觉：

| 相似度 | 0.10 | 0.20 | 0.26 | 0.50 | 0.60 | 0.80 | 1.00 |
|---|---|---|---|---|---|---|---|
| 基础分 | 25 | 38 | 44 | 66 | 74 | 87 | 100 |
| 旧口径 | 18 | 30 | 36 | 59 | 68 | 85 | 100 |

**7. 差异高亮**（纯算法）：把作业与参考答案做字面比对——用 5 字锚点定位、向两侧扩展成极大匹配，连续 5 字以上完全一致才算「相同」；剩下的区间（滤掉纯标点与不足 2 字的碎差异）标红。只做字符比对，不做语义判断，所以同义替换、语序调整也会被标红；但相似度里已给过同义加成，**红字面积不等于扣分幅度**。

**8. AI 修正**（可选）：把参考答案、学生作业与基础分一起交给模型，要求以基础分为锚点、在 ±15 分内修正，并输出 100 字以内评语；提示词明确要求同义替换、同义句改写、语序调整都按「内容正确」计分，要点讲全时应上调而非压分。只接受 JSON，解析失败则回落基础分。

## AI 评语（可选）

不填 Key 也能用——查重、打分、导出全部不受影响，只是没有模型评语。想启用评语，在「AI 配置」浮层里填三项：

| 字段 | 示例 | 说明 |
|---|---|---|
| 接口地址 | `https://api.deepseek.com/v1` | 任何兼容 OpenAI 协议的服务，必须 `http(s)://` 开头 |
| 模型名称 | `deepseek-chat` | 也可点「拉取列表」从服务商列表里选 |
| API Key | `sk-...` | 你自己的密钥 |

也可以点预设（DeepSeek / Kimi / 魔搭 / 通义千问 / 硅基流动 / OpenRouter 等）自动填好前两项，只需补 Key。填完点「测试连接」会发一条最小请求验证三元组是否可用。

**Key 的存放**：只写入当前浏览器的 `localStorage`，按服务商分别保存，切换预设自动回填；不会传给本页面以外的任何一方（除了你指定的模型接口）。公用电脑上用完请点「清除 Key」。

> ⚠️ `localStorage` 是明文存储，这是浏览器本地存储的固有性质。若要更严格的隔离，应把请求放到自己的服务端代理里。

## 跨域与代理

多数主流服务商（DeepSeek、魔搭、通义千问、硅基流动、OpenRouter、Z.ai）在响应头里放了 `Access-Control-Allow-Origin`，网页可以直连。少数未开放 CORS 的接口会被浏览器拦截。

「AI 配置 → 跨域代理」里可以填一个转发地址（用 `{url}` 占位，会被替换成编码后的真实接口地址），或者点「复制代理脚本」拿到一段零依赖的 Node 代理代码，本地 `node proxy.js` 跑起来后点「填入本地代理」即可。

## 已知限制

- 单文件版只处理纯文本（`.txt` / `.md` / 粘贴）；`.docx` / `.pdf` / `.csv` / `.json` 由**在线版**的后端解析，单文件版不解析
- 查重基于**词面共现 + 同义词归一**，能识别更换同义词、调整语序的改写，但整段换用教材原文之外的说法（真正的语义改写）仍可能低分——它衡量的是「概念词重合」，不是深度语义理解
- 同义句加成会抬高「措辞不同但要点一致」的分数，也意味着同一话题、同一套路的作业会略微偏高，判定时仍需人工复核
- 「对照高亮」是字符级比对：同义替换、语序调整都会被标红，红字多不代表答错，最终仍要人工判断
- 两两全比复杂度 O(N²)，几十份尚可，上百份会明显变慢
- 全部计算在主线程完成，超大文本（单篇上万字）时页面会短暂卡顿
- AI 评语质量取决于所选模型；评语需要联网，且会把你配置的作业文本发送到你指定的模型服务
- 配置跟着浏览器走，换设备或清缓存后需要重新填写
